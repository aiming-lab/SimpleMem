## Summary

Adds a PostgreSQL + pgvector backend implementing the `VectorStoreBackend`
protocol introduced in #76, following the same pattern as the Milvus backend
in #77.

LanceDB remains the default — no existing deployments are affected.

---

## What's new

**`simplemem/core/database/pg_vector_store_backend.py`** — `PGVectorStoreBackend`
- Implements `VectorStoreBackend` (insert / semantic_search / keyword_search /
  structured_search / count / get_all / optimize / clear)
- `semantic_score_order = ScoreOrder.ASCENDING` (cosine distance, lower = better)
- `keyword_score_order  = ScoreOrder.DESCENDING`
- Semantic search: pgvector HNSW index, `<=>` cosine operator; LIMIT inlined
  as a literal (required for IRIS compatibility)
- Keyword search: case-insensitive `LOWER(col) LIKE LOWER(%s)` matching against
  `lossless_restatement` and `keywords` columns — portable across PostgreSQL and
  IRIS (no tsvector / plainto_tsquery dependency)
- Structured search: parameterized WHERE with `LIKE '%"value"%'` for JSON array
  columns (persons, entities) and `LIKE %location%` for string columns — works
  on both PostgreSQL and IRIS (no `::jsonb @>` containment operator required)
- Thread-local connections (`threading.local()`) matching the existing
  parallelism model
- `VACUUM ANALYZE` as `optimize()` equivalent; silently skipped on backends that
  don't support it (e.g. IRIS)
- Schema bootstrap is idempotent: `CREATE TABLE IF NOT EXISTS`, index creation
  wrapped in try/except to handle duplicate errors gracefully

**`simplemem/core/database/__init__.py`** — `get_vector_store()` factory
- Returns a `VectorStore` whose backend is `PGVectorStoreBackend` when
  `STORAGE_BACKEND=pgvector` (or `backend='pgvector'` passed directly),
  otherwise falls back to the default `LanceDBVectorStoreBackend`
- `PGVectorStoreBackend` lazily exported (no hard psycopg import at module load)

**`simplemem/core/settings.py`**
- Two new settings: `STORAGE_BACKEND` (default `"lancedb"`) and `PG_DSN`

## Schema

```sql
CREATE TABLE memory_entries (
    entry_id              VARCHAR(512)  NOT NULL,
    lossless_restatement  VARCHAR(4000) NOT NULL,
    keywords              VARCHAR(4000),
    timestamp             VARCHAR(50),
    location              VARCHAR(1000),
    persons               VARCHAR(4000),
    entities              VARCHAR(4000),
    topic                 VARCHAR(500),
    vec                   vector(1024)
);

CREATE INDEX ON memory_entries USING hnsw (vec vector_cosine_ops);
```

All text columns use `VARCHAR(N)` rather than `TEXT` for compatibility with
backends (like IRIS via pgwire) where `TEXT` returns stream references.

## Opting in

```python
# config.py
STORAGE_BACKEND = "pgvector"
PG_DSN = "postgresql://user:pass@localhost:5432/mydb"
```

Or via environment variables:

```bash
export STORAGE_BACKEND=pgvector
export PG_DSN=postgresql://user:pass@localhost:5432/mydb
```

pip install "psycopg[binary]" pgvector

## Using PostgreSQL

Any PostgreSQL ≥ 15 instance with the pgvector extension works:

```sql
CREATE EXTENSION IF NOT EXISTS vector;  -- one-time setup
```

## Using InterSystems IRIS

IRIS does not natively speak the PostgreSQL wire protocol, but
[iris-pgwire](https://github.com/intersystems-community/iris-pgwire)
adds a translation layer so any psycopg client — including this backend —
connects to IRIS without IRIS-specific drivers.

**Server-side setup (one time per IRIS instance):**

```bash
# Install iris-pgwire on the machine running IRIS
pip install iris-pgwire

# Start the pgwire server (default port 5432)
python -m iris_pgwire.server
```

Or via Docker (see [iris-pgwire README](https://github.com/intersystems-community/iris-pgwire)):

```bash
docker compose up -d
```

**Then point PG_DSN at the pgwire endpoint:**

```python
# config.py
STORAGE_BACKEND = "pgvector"
PG_DSN = "postgresql://_SYSTEM:SYS@localhost:5432/USER"
```

iris-pgwire translates pgvector DDL and operators transparently — no code
changes are needed to switch between PostgreSQL and IRIS, only the DSN changes.

IRIS-specific SQL differences handled by this backend:

| PostgreSQL feature | IRIS behaviour | How we handle it |
|---|---|---|
| `CREATE EXTENSION IF NOT EXISTS vector` | Not supported | Wrapped in try/except — skipped silently |
| `CREATE INDEX … IF NOT EXISTS` | Not supported | `IF NOT EXISTS` removed; duplicate errors caught |
| `LIMIT %s` (parameterized) | Not supported | Limit inlined as integer literal |
| `TEXT` columns | Returns stream references | All text columns use `VARCHAR(N)` |
| `::jsonb @>` containment | Not supported | `LIKE '%"value"%'` on VARCHAR JSON columns |
| `ILIKE` | Not supported | `LOWER(col) LIKE LOWER(%s)` |
| `tsvector` / `to_tsvector` | Not supported | LIKE-based keyword search |
| `VACUUM ANALYZE` | Not supported | `optimize()` skips silently |

## Tests

| File | Tests | Run condition |
|---|---|---|
| `tests/test_pg_vector_store_backend.py` | 19 | `PG_TEST_DSN` env var |

Tests skip automatically without the env var — no CI infrastructure changes needed.
All 19 tests verified passing against both PostgreSQL and InterSystems IRIS
(via iris-pgwire).

```bash
PG_TEST_DSN=postgresql://postgres:postgres@localhost:5432/simplemem_test \
  pytest tests/test_pg_vector_store_backend.py -v
```

Covers: insert, semantic/keyword/structured search, score ordering, empty-input
guards, SQL injection resistance, optimize, clear + reinsert, and end-to-end
via `VectorStore` + `get_vector_store()`.
